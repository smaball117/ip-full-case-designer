# IP Full Case Designer — Skill 定位文档 v0.3 Draft

> 本文只定义这个 Skill **是什么、为谁服务、怎么工作、最终交付什么**。  
> 具体执行规则、Prompt、模板和目录结构后续再根据本定位重构。

---

# 1. 一句话定位

**IP Full Case Designer 是一个“参考驱动型 IP 创意全案 Skill”。**

用户提供：
- 一个初始想法；
- 若干参考图；
- 喜欢与不喜欢的方向；
- 分阶段补充的服装、海报、字体、周边、线下空间参考；

Agent 调用本 Skill 后，负责：
- 理解参考；
- 做创意发散；
- 帮用户选择方向；
- 逐步完成角色开发与视觉延展；
- 保持同一 IP 的一致性；
- 最终输出一整套可展示、可归档、可继续扩展的 IP 全案。

核心不是“自动原创一套完全脱离参考的设计系统”。

核心是：

> **用户负责提供审美判断、想法与参考，Agent 负责把这些零散输入转化成一个完整、连续、可执行的 IP 项目。**

---

# 2. 它不是什么

这个 Skill **不是**：

- 单张角色生成器；
- 单纯提示词生成器；
- 自动品牌战略工具；
- 完全不需要参考图的原创系统；
- 只会“照着参考图换角色”的仿图工具；
- 一次输入就自动跑到底、不给用户选择权的流水线。

它也不追求：

- 每一步都脱离参考图；
- 每个阶段都由 AI 自己决定；
- 强行建立过度复杂的品牌系统；
- 为了“系统化”而增加大量用户不需要的文件和规则。

---

# 3. 这个 Skill 真正解决的问题

很多 IP 项目并不是从一份完整 Brief 开始。

真实过程通常是：

```text
我有一个想法
↓
我找到一些喜欢的参考图
↓
我不知道怎么整理成自己的方向
↓
AI 做了几张，但每一步风格都容易漂
↓
换装、海报、Logo、周边又要重新解释
↓
最后得到很多图，但不像一个完整项目
```

这个 Skill 要把它变成：

```text
想法 + 参考
↓
参考理解与创意发散
↓
方向选择
↓
角色设定
↓
草图探索
↓
角色定稿
↓
3D / 三视图 / 表情 / 换装
↓
Logo / 字体 / 海报
↓
周边 / 线下物料
↓
项目归档
↓
复盘与后续扩展
```

---

# 4. 核心工作模式

## 4.1 用户是创意决策者

用户不需要一次性写完整 Brief。

用户可以只给：
- 一个想法；
- 几张参考；
- 一句“我喜欢这个，但不要这么幼稚”；
- 一张服装图；
- 一张海报图；
- 一个字体方向。

Skill 要主动把这些碎片整理成可执行信息。

用户始终拥有：
- 方向选择权；
- 风格确认权；
- 角色锁定权；
- 是否继续进入下一阶段的决定权。

---

## 4.2 Agent 是 IP 项目总控导演

Agent 不是只负责“生成”。

Agent 需要同时完成四件事：

### Creative Director
从想法和参考里提出 5 个真正不同的方向。

### Character / Visual Designer
把选定方向发展成角色、换装、视觉和应用。

### Consistency Controller
保证角色、配色、符号和气质不会每一步重新长一遍。

### Asset / Project Manager
把每一步产出归档到正确目录，并记录哪些已确定、哪些待修改。

---

# 5. 参考图的正确定位

参考图是本 Skill 的重要输入。

**不需要刻意弱化参考。**

但 Skill 不能只做：

```text
参考图 → 换成我的角色
```

而应该先判断：

```text
这张参考图，我到底想借什么？
```

常见参考类型：

- 角色造型参考
- 面部 / 五官参考
- 比例参考
- 材质参考
- 配色参考
- 服装参考
- 姿势参考
- Logo / 字体参考
- 海报构图参考
- 周边参考
- 线下空间参考

每张参考图都应先被整理成：

```text
参考什么：
不参考什么：
用在哪一步：
优先级：
```

这样可以：
- 保留用户真正喜欢的部分；
- 避免把参考图整张照搬；
- 避免多张参考互相打架；
- 方便后续统一设计。

---

# 6. 完整工作流

## Stage 00 — 项目建立

输入：
- 项目名（可以暂定）
- 初始想法
- 已有参考图

输出：
- 项目文件夹
- 项目状态
- 参考图分类

---

## Stage 01 — 参考理解 + 轻量 Brief

Agent 先理解：
- 用户想做什么；
- 哪些是必须保留；
- 哪些是喜欢的视觉特征；
- 哪些绝对不要。

如果信息足够，不重复问。

如果信息不足，只问会真正影响方向的问题。

---

## Stage 02 — 5 个创意方向

基于：
- 用户想法；
- 参考图；
- 目标受众；
- 未来应用；

输出 5 个不同方向。

每个方向至少说明：
- 方向名；
- 核心概念；
- 角色气质；
- 世界观 / 故事钩子；
- 视觉方向；
- 商业延展；
- 风险。

用户选择：
- 1 个方向；
- 或最多 2 个方向组合。

这是第一个重要确认点。

---

## Stage 03 — IP 设定清单

方向确认后，整理成可编辑的 IP Brief：

- 名称；
- 中英文名；
- 身份；
- 性格；
- 小缺点；
- 喜欢 / 讨厌；
- 世界观；
- 核心故事；
- 标志物；
- 配色倾向；
- 目标人群；
- 主要应用；
- Must Keep；
- Must Avoid。

Skill 可以补全逻辑，但不能擅自把未确认设定写死。

---

## Stage 04 — 5 张角色草图

基于已确认设定和角色参考，输出 5 个草图方向。

草图阶段重点探索：
- 头型；
- 五官；
- 身体比例；
- 耳朵 / 发型；
- 帽子；
- 蝴蝶结；
- 道具；
- 轮廓识别。

要求：
- 5 张是同一个 IP 的设计探索；
- 不是 5 个完全不同角色；
- 不追求最终渲染效果；
- 重点看轮廓与识别。

用户选定一个版本，或指定融合。

---

## Stage 05 — 角色定稿 / 3D

选定草图后：

1. 精修角色；
2. 根据材质参考完成 3D 渲染；
3. 调整五官、比例、配件；
4. 用户确认最终角色。

角色确认后，才进入批量延展。

---

## Stage 06 — 角色资产系统

### 三视图 / 四视图
- 正面
- 侧面
- 背面
- 可选 3/4 Hero View

### 表情九宫格
强调“角色性格”，不是只换嘴。

### 动作九宫格
根据角色行为与世界观设计。

### 换装九宫格
用户可提供服装参考。

Skill 负责：
- 提取服装轮廓；
- 提取配色；
- 提取层次；
- 转译为角色自身比例和风格；
- 不照搬参考模特。

---

# 7. 品牌视觉延展

角色资产稳定后，再进入视觉应用。

## 7.1 2D 扁平化

根据 3D 角色输出：
- 扁平全身；
- 半身；
- 头像；
- 线稿；
- 单色；
- Sticker / Icon。

目的是让角色真正能进入平面设计。

---

## 7.2 Logo / 字体

用户可提供：
- Logo 参考；
- 字体参考；
- 字形气质参考。

Skill 需要输出：
- 中文 Logo；
- 英文 Logo；
- 中英组合；
- 主色版本；
- 单色版本；
- 简化标志。

重点是“根据参考转译”，不是直接复制字形。

---

## 7.3 海报 / KV

用户可以提供：
- 海报参考；
- 构图参考；
- 字体参考；
- 主题想法。

Skill 应先做：
1. 主题理解；
2. 构图提炼；
3. 元素取舍；
4. 角色优先级判断；
5. 再生成。

常见输出：
- 3:4 竖版；
- 16:9 横版；
- 1:1 社媒版。

不能因为参考图元素多，就把所有元素照搬。

---

# 8. 商业应用

## 8.1 周边

根据前面已经完成的资产，选择合适的形式：

- 手办；
- 毛绒；
- 徽章；
- 亚克力；
- 挂件；
- 贴纸；
- 明信片；
- 帆布袋；
- 杯子；
- 手机壳；
- 包装；
- 盲盒；
- 礼盒。

不是每个产品都必须放完整角色。

应该根据产品尺寸选择：
- Logo；
- 头像；
- 全身；
- 图标；
- Pattern；
- 超级符号。

---

## 8.2 线下物料 / 空间

用户先选择或提供参考：

- 室内；
- 户外；
- 快闪；
- 市集；
- 展陈；
- 店中店。

Skill 再帮助完成：
- 主题；
- 门头；
- 主背景板；
- 拍照点；
- 人形立牌；
- 展示台；
- 指引牌；
- 包装袋；
- 互动装置。

需要从 IP 世界观出发，不是单纯给一个普通空间贴角色贴纸。

---

# 9. 最终交付

每个完整 IP 项目最终应形成：

```text
PROJECT_NAME/
│
├── 01_brief/
├── 02_references/
├── 03_concept-directions/
├── 04_sketch/
├── 05_character-final/
├── 06_3d/
├── 07_turnaround/
├── 08_expressions/
├── 09_actions/
├── 10_outfits/
├── 11_2d-assets/
├── 12_logo-typography/
├── 13_posters/
├── 14_merchandise/
├── 15_offline/
└── 16_review/
```

最终结果不是“一张最终图”。

而是：

> **一个完整的 IP 项目资产包。**

---

# 10. 最终复盘

项目结束后，Skill 自动给出：

## Keep
哪些内容已经稳定，可以继续保持。

## Improve
哪些内容还不够统一或不够有识别度。

## Extend
下一步可以扩什么：
- 新表情；
- 新服装；
- 新主题；
- 配角；
- 新周边；
- 新空间。

## Reuse
这次项目中哪些方法可以复用到下一套 IP。

---

# 11. Skill 成功标准

一个好的执行结果，不是“每张图都很好看”。

而是同时满足：

1. 用户能看见完整的创意过程；
2. 用户可以在关键节点做选择；
3. 参考图被正确理解和使用；
4. 每个阶段都继承前面的角色与视觉；
5. 不会每做一张图就重新设计角色；
6. Logo、海报、换装、周边属于同一个 IP；
7. 最后形成完整项目文件夹；
8. 项目结束后还能继续扩展，而不是一次性用完。

---

# 12. 最终定位声明

**IP Full Case Designer 的目标不是替用户完成审美判断，而是把用户的想法、参考和选择，持续转译成一套完整 IP 全案。**

它的角色更接近：

> **AI IP 创意总监 + 角色设计协作者 + 视觉延展助手 + 项目资产管理器**

工作方式是：

> **用户提供灵感与判断，Skill 提供创意方法、连续执行与完整交付。**
