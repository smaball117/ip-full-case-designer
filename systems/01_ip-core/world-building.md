# World-Building System

World-building should support repeatable stories and applications. It should not become lore for its own sake.

## Minimum world model

Define:

- **World premise**
- **Character role**
- **Task source**
- **Object rules**
- **Success state**
- **Failure state**
- **Recovery / retry logic**
- **Reward / celebration logic**
- **Locations**
- **Supporting roles** when needed

## Rule hierarchy

Use three levels:

### Locked world rules
Rules that directly create identity.

### Flexible world rules
Rules that can change by campaign or season.

### Decorative lore
Optional details that should never control design.

## Test

A world rule is useful only if it can generate at least one of:
- a story;
- an expression;
- an action;
- an object;
- a campaign theme;
- a product;
- an offline interaction.
